# Student Performance Analytics & Early Prediction

**End-to-end Data Science project** aligned to the eight-week internship plan: Python, Pandas/NumPy, EDA, supervised ML, unsupervised learning extension, evaluation, dashboard deployment, and final reporting.

## Research question
Can student context, study habits, support indicators, and absences provide a useful estimate of final Mathematics grade (`G3`) before the final assessment?

## Dataset and provenance
- **Source:** UCI Machine Learning Repository, Student Performance, dataset ID 320.
- **Citation:** Cortez, P. (2008). *Student Performance* [Dataset]. UCI Machine Learning Repository. https://doi.org/10.24432/C5TG7T
- **Official page:** https://archive.ics.uci.edu/dataset/320/student+performance
- The UCI collection includes Mathematics and Portuguese language datasets. This project is intended to use the Mathematics subset.
- The data concerns two Portuguese secondary schools; it is not a representative sample of all schools or countries.
- Dataset license: CC BY 4.0. Keep attribution when redistributing.

The data is fetched from the official UCI archive at runtime, specifically `student-mat.csv`. An internet connection is required on the first run. No synthetic rows are passed off as real data.

## Modeling choices
- Target: `G3`, final grade on a 0–20 scale.
- Primary use case: early prediction. `G1` and `G2` are intentionally excluded because they are earlier grades that strongly correlate with `G3`; using them would answer a different, easier question and risk target leakage relative to the early-intervention use case.
- Split: 80% train / 20% held-out test, fixed `random_state=42`.
- Model selection: five-fold cross-validation on training data, selecting the lowest mean MAE.
- Candidates: mean baseline, Ridge regression, Random Forest, Histogram Gradient Boosting.
- Metrics: MAE, RMSE, R². The baseline helps check whether ML models outperform a naive prediction.
- Preprocessing is fitted inside an sklearn Pipeline, avoiding leakage from fitting imputers/scalers/encoders on the test data.

## Run on Windows
Use Python 3.10 or newer (Python 3.10 is a sensible option if that is your installed environment).

```powershell
cd path\to\student_performance_project
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python train.py
streamlit run app.py
```

If PowerShell blocks activation, run the venv Python directly:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe train.py
.\.venv\Scripts\python.exe -m streamlit run app.py
```

## Output artifacts
The training script writes the actual run outputs to `artifacts/`:
- `source_data_snapshot.csv`
- `model_metrics.csv`
- `test_predictions.csv`
- `run_metadata.json`
- `best_model.joblib`

Metrics are generated by running the pipeline; they are deliberately not hard-coded in advance. Record the output from your own run in the report.

## Interpretation and ethics
This is an educational prototype, not a validated decision system. Predictions may be inaccurate, and patterns are associations rather than proof of causation. Do not use the model to label, punish, rank, or deny opportunities to students. Any real deployment would need local validation, consent/governance review, subgroup error analysis, human oversight, and a clear appeal process.
